# 珠算界面重构设计规范 · 烟雨江南

**版本** v1.4 · **适用范围** Wails 桌面客户端全部界面（登录、登录后五页、页面未找到） · **状态** 已实施，本版按实测值回写

本文以确认后的「烟雨江南」首页、四张业务原型以及后补的登录与页面未找到两张原型为视觉基准，并以 primordialweave/zhusuan 的现有路由、接口和权限为功能基准。原型图确定构图、层级和材质，不是数据源。**工作台按原型完全还原**，其余页面以原型为参考、按现有能力调整：**结构、层级和材质跟原型，字号和密度跟本文 4.2 与第 6 节**（原型里业务页的字号是本文的 1.4–1.5 倍，照搬的话 1280 × 800 的默认窗口里项目表只剩三四行）。文中尺寸均为 CSS px。几何与颜色数值已在 Chromium 预览里逐页量过；性能数字是实现目标，尚未在目标客户端实测。

## v1.4 修订（2026-11-19）

- **工作台摘要可切换范围。** 点饼图在 全部 → 本年 → 本月 之间循环；范围写在两行标签里（本年已收款 / 本年待收款），选择记在本机。本年、本月是自然年、自然月，口径和数据分析的自选范围相同。
- **项目管理只滚动数据行。** 标题行、表头和分页固定，表格在自己的区域里滚动；窗口矮到放不下几行时整页才滚。
- **数据分析的自选范围。** 周期标签在「年」之后多一项「自选」，选中后出现年、月两个下拉（月份第一项是「全年」），指标、趋势图和导出都按所选自然年或自然月计算。接口：`/dashboard/stats` 与 `/dashboard/income-trend` 接受 `year`、`month`（`month` 缺省或 0 表示整年），传了 `year` 就忽略 `period`。
- **导出。** 导出报表、导出项目（列表菜单和详情页）都生成 CSV；项目导出包含项目信息和全部收款节点。桌面端由 `internal/desktop.FileExporter` 弹系统保存对话框写文件（WKWebView 不处理下载链接），浏览器里走下载。
- **图标。** 图标字体的盒子固定为一个字高的正方形（`foundations/typography.css`），分页的箭头和省略号都用图标而不是文字字符；`IconButton` 的图标按按钮尺寸取 16 / 18 / 20px。
- **系统设置（替代 v1.3 的描述）。** 页面由 `SettingsGroup`（标题 + 卡片 + 可选的底部操作行）堆叠而成。个人信息页自上而下是账户卡、个人信息卡、安全设置卡，保存按钮都在各自卡片底部操作行的右端；不再有单独的安全设置分类。外观页是三张主题缩略图单选卡和三个开关行。用户、字典、访问令牌是表格，通知是卡片里的行。
- **人物。** `SceneGreeter` 的三帧不加 CSS 滤镜，并且始终各占一个合成层（静止帧与挥手帧走同一条渲染路径）。

## 0. 与当前系统架构的对应

v1.0 按 Vue 单文件组件和 `--or-*` 令牌撰写。当前前端是 **React 19 + TypeScript + React Router 7 + Zustand + Tailwind 4**，视觉公共层是 **珠算设计系统（ODS）**，由契约测试守护。本版把所有落地约定改到这套架构上，冲突处以本节为准。

| v1.0 写法 | 当前架构中的落点 |
|---|---|
| `AppLayout.vue`、`AppHeader.vue`、`App.vue` | `components/layout/AppLayout.tsx`。旧 `AppTopbar.tsx` 移除，通知迁到 `NotificationEntry.tsx`，账户与退出迁到设置页 |
| `RouterView`、`meta.dockKey` | `createBrowserRouter` + `<Outlet />`。Dock 归属由 `primaryNavigation.ts` 的路径匹配表决定，不引入路由 meta |
| `Teleport` 共用根层 | ODS `Popover`、`Modal`、`Drawer`、`Toaster` 已各自 portal 并经 `overlayStack` 管理层级，业务代码不直接 `createPortal` |
| Pinia store、composable | Zustand store（`stores/theme.ts`、新增 `stores/appearance.ts`）与 React hooks |
| `--or-*` 令牌、`orange-tokens.css` | ODS 三层令牌：`tokens/reference.css` → `tokens/semantic.css` → `tokens/themes/*.css`。页面只消费 `--ods-*` 语义令牌，见 4.1 的映射表 |
| 浅色／深色两套主题 | `themes/jiangnan-mist.css`（烟雨，浅色）与 `themes/jiangnan-night.css`（夜雨，深色），替换原 Day Ember／Night Orbit |
| `StatusBadge.vue`、`SegmentedControl.vue`、`WorkSurface.vue` | ODS 的 `Chip`、新增 `SegmentedControl` 组件、新增 `WorkSurface` 模式。旧 `StatusBadge` 路径受迁移契约禁止重建 |
| 页面里手写按钮、表格、弹层 | 迁移契约禁止生产 TSX 出现原生 `button`、`a`、`input`、`table`、`dialog`、`img` 以及带 `onClick` 的容器。交互一律用 ODS 组件或在 ODS 内新增 |
| 页面 CSS 改组件外观 | 样式归属契约禁止页面 CSS 重绘 `.ods-*`。新外观通过令牌或 ODS 变体实现 |

已经存在、无须新建的能力：底部 `AppDock`（此前仅窄窗显示）、`useRouteScroll`（路由滚动恢复与标题聚焦）、`useReducedMotion`、主题 store 的 `auto` 值与防闪烁启动、`overlayStack`、`readDesignToken()` 式的图表取色、MiSans 本地字体。

每次改动的验收命令：`cd frontend && npx tsc --noEmit -p tsconfig.app.json && npx vitest run && npx eslint src --max-warnings=0 && npm run build`。类型检查必须指到 `tsconfig.app.json`：根 `tsconfig.json` 只有 references，`tsc -p .` 什么都不检查。

## 1. 重构目标与边界

**首页是可以停留的动态雨景，业务页是可以高效工作的台面。** 只在工作台播放完整江南动效。进入项目、日历、分析或设置后，江南退为静态背景，让文字、日期和金额成为第一视觉层。全局保留同一个底部 Dock，切页时只移动选中态，不更换位置或尺寸。

- **保留**现有登录与鉴权、五个顶级入口、项目与款项增删改查、通知与未读状态、账号与退出、设置权限、后端业务校验。
- **改动**登录后应用外壳、Dock、首页场景和收款摘要、四个业务页的布局和样式，登录页和新增的页面未找到页，以及它们使用的主题与通用组件。
- **不在本次自动改动**Go 数据库结构、API 访问权限、统计定义、登录与记住密码的逻辑、应用图标及品牌资源。新的客户精确筛选、报表导出行为、统计口径变更、演示模式、自助重置密码不能由一张原型图推定为已有能力。
- **原型中有意保留的差异**工作台显示实心两段饼图，分析页显示两段环形图。首页无左上角品牌字标；macOS 保留系统窗口控件，Windows 使用透明自定义拖动区和右上胶囊窗口按钮。桥上的女童只出现在工作台主景，业务页及设置预览可以使用无人物静帧。

## 3. 应用外壳与窗口布局

### 3.1 结构

```text
AppLayout.tsx（仅登录后，ProtectedRoute 之内）
├─ JiangnanScene                静帧兜底，工作台按需叠加动画
├─ .app-titlebar-drag-region    仅使用现有 Wails 窗口拖拽机制
├─ main.app-main
│  └─ <Outlet />
│     ├─ DashboardView         场景上方只有收款摘要
│     └─ WorkSurface           页面标题、工具区、内容区
├─ AppDock                     五个一级入口，始终居中
├─ NotificationEntry           有未读时出现在 Dock 右侧
└─ ODS 浮层（各自 portal）       菜单、通知详情、确认框、Toast
```

- 现有 `AppLayout.tsx` 由顶栏 `AppTopbar`、窄窗 Dock、整页滚动和 `useAmbientLight` 鼠标追光组成。移除顶栏和追光（含 `pointermove` 监听与三组未使用的 SVG 滤镜），Dock 改为全尺寸常驻，滚动收进工作面板。`App.tsx` 不挂任何全局鼠标监听。
- macOS 保留系统红黄绿按钮，不绘制假按钮。Windows、Linux 不复制 macOS 三色按钮，沿用各平台 Wails 窗口外框。拖拽区不能覆盖 Dock、标题操作、输入控件或设置分段。隐藏字标不等于移除拖动区域。
- 从现有 `AppTopbar.tsx` 迁移通知铃、未读角标、通知详情和账户退出。首屏不恢复旧顶栏。Dock 右侧仅在有未读时显示一枚独立的通知按钮（`NotificationEntry`），点击打开通知弹层，点“系统设置”本体仍正常导航，无未读时从设置页的通知标签进入。账户与退出迁入设置页的个人信息区域，主题切换迁入外观设置。通知入口必须在键盘导航下可达，且不得把一个按钮嵌套到另一个可交互元素。组件展厅 `/design-system` 保留路由，入口移到设置页的开发设置，不占 Dock。
- 采用局部滚动。业务面板内部可以滚动，Dock 不随内容滚动，末行、分页、表单提交始终能滚到 Dock 上方。对表格可在表格容器内横向滚动，不让整个窗口横向滚动。
- 推荐层级：静帧 0、动效 10、业务内容 20、Dock 30、浮层 40、Toast 50、模态框 60。弹层和模态框沿用 ODS 自带的 portal 与 `--ods-z-*` 层级，避免被业务面板裁切。

### 3.2 尺寸与适配

| 项目 | 标准桌面 ≥ 1360 | 常用窗口 1100–1359 | 紧凑窗口 < 1100 |
|---|---|---|---|
| 内容面板 | 外边距 68–96，最大宽 1440，顶部 71–82 | 外边距 45–68，顶部 48–70 | 外边距 20–45，顶部 44–48 |
| 面板内边距 | 水平 48，垂直 40 | 水平 41–48，垂直 34–40 | 水平 20–40，垂直 20–34 |
| Dock | 689 × 102.5 封顶（原型实测），底距 43 | 约 593 × 88，底距 37（1280 宽时） | 最小 560 × 76，底距 16–30 |
| 首页摘要 | 约 384 × 104，与 Dock 间隔 24–30 | 340–384 × 88–96，间隔 18–24 | 300–340 × 80–88，间隔 12–18 |
| 日历／分析 | 双栏 | 视内容宽度保留双栏 | 内容区不足 920 时上下堆叠 |
| 项目表 | 全列 | 金额和主状态优先 | 次要字段放详情，必要时表格局部横滚 |
| 设置 | 左侧设置行，右侧预览 | 预览缩小 | 预览移到表单下方或折叠 |

现有 Wails 默认窗口为 **1280 × 800**，必须先在此尺寸验收。1487 × 1058 用于和原型逐像素比对（此时面板实测 `80, 81, 1327 × 803`，面板底到 Dock 顶 28），1024 × 720 用于紧凑验收。Dock 与面板的尺寸都是 `clamp()` 令牌（`--ods-shell-dock-*`、`--app-surface-*`），上表是各档窗口下的实测结果，不是另外写死的值。如允许窗口更窄，Dock 应缩到视口宽度减 24px，保留五项及完整焦点，不靠硬裁切。高度 < 760 时先压缩面板留白、Dock 底距与首页摘要，保留点击热区。工作区底部预留至少 `Dock 高度 + 底距 + 24px`。短而宽的窗口使用单独场景构图或安全裁切，不能裁掉女童头部或桥拱。

原始色板放在 `tokens/reference.css` 的 `--ods-ref-color-jade-*`（青绿）、`mist-*`（雾灰绿）、`gold-*`（浅金）中，业务与组件不得直接引用。主按钮与选中态使用浅青绿底配墨绿字（`--ods-color-accent-fg`），不使用深色实心按钮。新增令牌须同时在两套主题定义，并登记到 `tokens.contract.test.ts` 与 `docs/design-system/tokens.md`。

- 色彩命名按用途，页面 CSS 不出现十六进制色值。金额正文用墨绿文字，浅金只做区分，不做浅底上的正文色。计划趋势线在浅面板上使用更深的金色（如 `#8D6C29`）并配虚线，区分不只依赖颜色。
- 业务面板半径 28–36，薄亮边 1px，避免每个区块套一张玻璃卡。用空隙和细线分组。面板下背景允许隐约透出，不可透出高反差枝叶到字下。
- Dock 单一连续玻璃体，圆角为高度的一半。玻璃由半透明填充、24px 背景模糊加 115% 饱和、边缘 2px 的高光环（`--ods-material-glass-specular`，左上最亮）和浅接触阴影构成。边缘折射是增强项，不能作用于图标和文字。跨 WebView 不将 SVG displacement 的 `backdrop-filter` 组合当成必备实现。
- 登录与未找到页的卡片是**磨砂**，不是玻璃：不做实时模糊，而是把一张预模糊的小静帧（`scene-frost.webp`）以和页面背景相同的裁切、`background-attachment: fixed` 画在卡片里，再盖一层 `--ods-material-frost-veil`。原因是卡片的海棠角靠九宫格遮罩裁出来，而 `backdrop-filter` 不会被遮罩裁掉。卡片及其祖先不能有 `transform`。
- 不支持背景模糊或用户关闭玻璃时，使用更实的底色、边框和阴影，尺寸不变。优先避免全屏 blur、叠加多层实时 blur、鼠标追光和长时辉光。
- 面板、图例、输入和 Dock 在实际合成背景上验证对比度。正常文本目标至少 4.5:1，主要图标、焦点、用于识别的控件边界目标至少 3:1。`tokens/contrast.test.ts` 对两套主题自动校验文字、软色底和渐变色标。

### 4.2 字体、间距与图标

| 项目 | 规范 |
|---|---|
| 页面标题 | 36–42 / 1.2，紧凑 30–34，使用 `--ods-font-family-title` 系统宋体栈，字重 `--ods-font-weight-title`（900，Songti SC Black） |
| 小节标题 | 20–24 / 1.35，中等字重 |
| 正文／表格 | 14–16 / 1.5，系统中文无衬线，优先清晰 |
| 次要说明 | 13–14 / 1.5，长说明避免挤占核心字段 |
| 金额／百分比 | 正文字体，开启 `font-variant-numeric: tabular-nums` |
| Dock | 图标 28–36，字 13–15（字重 450），图标与文字间距 4–6.6；均为原型按窗口宽度换算的 `clamp()` |
| 交互与节奏 | 常用间距 4/8/12/16/24/32/48，按钮高 36–44，Dock 热区不小于 44 × 44 |

标题字体栈 `"Songti SC", "Noto Serif SC", "Source Han Serif SC", STSong, SimSun, serif`，只用于页面一级标题，不随包分发宋体。登录与未找到页的大标题用楷体栈 `--ods-font-family-brush`（`"Kaiti SC", STKaiti, KaiTi`，再回落到宋体栈），未找到页的「404」用斜体衬线数字栈 `--ods-font-family-numeral`（`Baskerville, Didot, "Bodoni 72", Georgia`）；两者同样不随包分发，没装就回落。正文沿用已随包的 MiSans VF（字体资产契约要求唯一的 `@font-face`，且不得重新引入 Inter），小节标题、表格和数字都用它。离线可用，不依赖 CDN。图标继续使用 Remix Icon。所有金额经同一个格式化函数，保留非零小数，不把有效分币四舍五入为整数。对没有值显示“—”，有真实零值显示“¥0”。

## 5. 导航、通用交互与状态

| Dock 项 | 激活条件 | 图标语义 |
|---|---|---|
| 工作台 | `dashboard` | 小屋 |
| 项目管理 | `projects`、`project-create`、`project-edit`、`project-detail`、`payment-create`、`payment-create-global` | 文件夹 |
| 收款日历 | `calendar` | 日历 |
| 数据分析 | `analytics` | 柱状图 |
| 系统设置 | `settings`，忽略其 query | 齿轮 |

- 项目详情及表单是项目入口下的任务态，不加第六个 Dock 项。`primaryNavigation.ts` 为每个入口列出显式的匹配路径（项目入口含 `/projects/*` 与 `/payment/create`），不靠单一前缀推断全局添加收款。保留 `ProtectedRoute` 鉴权和深链行为。登录页与未找到页在 `AppLayout` 之外，不挂 Dock 或场景循环，见 6.6、6.7。
- Dock 为带名称的 `nav`，链接使用 `aria-current="page"` 标记当前主入口，支持 Tab / Shift+Tab 和 Enter。焦点环与当前选中样式必须能同时看清。键盘切页后由 `useRouteScroll` 把焦点送到主标题，后退时恢复滚动位置，它监听的滚动容器改为工作面板。弹层关闭后恢复触发点焦点。
- Hover 只提亮和轻抬 0–2px，按压缩至 .98，选中切换约 160–200ms，页面淡入约 120–180ms。不要模仿系统 Dock 大幅放大。减少动态时取消位移和连续动画。
- **加载**维持布局，使用静态占位，不以 0 冒充尚未加载。**空白**展示明确空状态和最相关的下一步。**失败**就地显示错误和重试，旧数据若保留必须标示未更新。**成功**保留既有 Toast。不得把后台加载遮罩覆盖全场景或劫持键盘焦点。
- 菜单、表单和确认框复用现有业务交互。删除、归档不得共享同一个模糊文案。取消编辑或提交失败不清空未保存输入。可见字段收起时，信息仍可从详情或列设置访问。

## 6. 各页面的详细规格

### 6.1 工作台

**布局。** 场景全铺。左上只留真实原生控件，画布上不放 Logo、标题、横幅、数据卡组或业务快捷按钮。石桥拱顶在画面横向约 30%、纵向约 44% 的区域，水线在约 60%。柳枝从右上垂下，山雾与粉墙黛瓦在中后景。女童站在桥面中央偏左，穿浅杏与淡青的交领汉服，正面朝向用户微笑。完整角色尺度参考画面高度约 8%–12%，应由近侧石栏遮住对应的下半身，不能把人物漂浮在桥栏前。人物是场景的一部分，不是头像、按钮或前景大立绘。

**收款摘要。** Dock 正上方居中，左侧 54–68px 的两段实心饼图，右侧两行“已收款金额”“待收款金额”。图例圆点、文本和金额按列对齐，缩小时优先缩短面板内边距，不能切掉金额。饼图只展示构成，保留独立可读的 DOM 金额。避免用 Canvas 同时画不可访问的文字。首版摘要为展示态，不在未定义交互时让整块看起来可点击。

**数据。** 只调用 `dashboardApi.getStats()` 的无周期全量口径。项目仓储当前按所属用户的合同总额减实收得到待收，因此不能把逾期再加一遍。两个值均为 0 时显示中性空圆和“暂无收款数据”，不画假扇区。一项为 0 时另一项显示完整圆。金额异常（例如超收导致待收为负）保留真实账务信息，图形不画负扇区，可显示“已超收 ¥…”或“待收金额异常”并允许去业务页核查，不能静默截断文字数值。切回首页或相关写操作成功后刷新摘要，画布启动不依赖接口返回。

**迁移旧首页入口。** 新建项目放在项目页工具栏，添加收款放在项目行菜单／详情，保留全局添加路由，近期应收在收款日历中承接，原趋势和财务指标迁到数据分析。已逾期可在分析指标和日历状态中找回。最近项目列表可并入项目页的最近更新视图，需真实排序能力时单独验证，不改变首页构图。

### 6.2 项目管理

**布局。** 面板顶左“项目管理”和一句说明，顶右“新建项目”。其下工具栏：名称／客户关键词搜索、状态筛选。项目表为页面核心，行高 52–64，金额右对齐，主列优先。高信息密度通过细分隔线组织，不用卡片列表代替台账。

| 列／操作 | 来源与交互 |
|---|---|
| 项目名称 | `name`，可点击进入 `/projects/:id`，键盘也可打开 |
| 客户 | `company`，长文截断并提供完整文本 |
| 截止日期 | `end_date`，仅业务日期，不做不必要的时区位移 |
| 合同金额、已收款 | `total_amount`、`received_amount`，右对齐 |
| 收款进度 | `received_amount / total_amount`，用条形加百分比。分母为 0 显示“—”，超收时进度条最多满格但显示真实百分比 |
| 状态 | 保留仓库状态映射和服务器筛选。项目“进行中／已完成”等与款项“待收／逾期”是不同枚举 |
| 操作菜单 | 按现有权限及处理函数承接编辑、添加收款、导出项目、归档、删除，危险操作确认 |
| 次要字段 | 起始日期、创建日期、管理员可见创建人等保留在详情或可展开列，不把原型简化当成字段删除 |

**搜索和分页。** 使用 `projectApi.list({ page, page_size, status, keyword })`。状态或关键词改变回到第 1 页，防抖建议 250ms，处理快速请求乱序。无搜索结果显示“清除筛选”，无任何项目显示“新建项目”。返回列表恢复搜索、筛选和页码，可用 route query 或 store。原型“全部客户”是视觉提案，当前列表接口没有独立客户参数。首版用现有关键词匹配客户，或者等后端支持独立过滤后再上该下拉，不能只筛当前分页冒充全量筛选。

**详情和表单。** 延用现有 `ProjectDetailView`、`ProjectCreateView`、`PaymentCreateView`。统一工作台面、面包屑或返回链接、字段间距和底部保存区。项目详情的“添加收款”预填当前项目，合同编号生成／校验、款项字段校验和现有权限不变。

### 6.3 收款日历

**布局。** 左侧月历约 68%–72%，右侧选中日期明细与近期收款。采用一块工作面板，中间一条竖分隔线。上一月、本月、下一月均保留。周列为“日 一 二 三 四 五 六”。月历只画当月需要的周数（四到六行），跨月格留空且不可点。月历撑满面板高度，右栏内容自己滚动，再长也不会把月历推出视口。

**数据和动作。** 保留 `paymentApi.list({start_date, end_date})` 和 `payment_stage` 字典。首版按 **计划收款日 `plan_date`** 分组，收款状态是该笔计划的当前状态。选中日期后右栏显示同日全部款项、项目、阶段、金额及“已收／待收／逾期”。已收可附实际到账日 `actual_date`，但不能用它悄悄改变日历归属。若后续支持“实际到账日视图”，需同步核查服务端筛选字段和查询覆盖范围。

- 日期格优先显示日期和最多两条款项摘要，多余显示“+N 笔”。同一天多条混合状态不能只显示一个绿色点。今日和选中日视觉分开，可用细描边和浅青填充区分。
- 首次进入选择今天。切月后选择当月合理日期（优先保留原日号并截到月底），点击“本月”回到当前月与今日。右栏与日期同帧更新，不保留上月的选中明细。
- “近期收款”建议指当前月今天起的未收计划，按日期排序。若仍使用仓库现有当月清单逻辑，应把标题改为“本月收款”，避免误称未来计划。
- 金额与状态都为可读文本。日期格以按钮实现，可为日历区域增加方向键、Enter/Space 选中和月份变更播报。无该日计划、无月数据、接口错误需分别处理。

### 6.4 数据分析

**布局。** 顶部标题及“周／月／季／年”分段。其下是一行四项指标，下面左侧趋势约 65%，右侧收款结构约 35%。图例接近各自图表，逾期保留独立指标而非重复做第三个扇区。窄窗口允许指标 2 × 2、两图上下堆叠。

| 项目 | 实现口径 |
|---|---|
| 预期收款 | 周期内 `total_amount`，按计划收款日 `plan_date` 聚合 |
| 收款率 | 保留现有 `paid_amount / total_amount` 公式。分子按实际到账日 `actual_date` 聚合、分母按计划日聚合，所以提前或补收的款项会让它超过 100%。分母为 0 时展示“—”并说明无计划收款，不把它当 0% 的业务结论 |
| 逾期比例 | `overdue_amount / total_amount`，待收包含逾期，不可再累加 |
| 平均收款周期 | 当前 `avg_collection_days` 实际是已到账款项的“实际到账日 − 计划收款日”平均差。建议 UI 名称用“平均到账偏差”，或保留原名并明确解释提前为负、延后为正。零样本和真实零不能由目前的 0 值可靠区分，若要区分需接口提供有效样本数 |
| 收款结构 | 两段环形图，仅 `paid_amount` 与 `pending_amount`，用两者之和算扇区占比。必要时在待收图例旁补充“其中逾期 ¥…”；此占比不等同上方收款率 |
| 收款趋势 | 用 Chart.js，将当前柱图改成实际实线、计划虚线。现有 `actual_values`、`expected_values` 是分时间桶金额，不是累计曲线。默认按原数据绘制，不强行单调，不把原型的平滑上升当成业务定义 |
| 导出报表 | 已实现：把当前周期的指标和趋势导出为 CSV（`utils/csv.ts` 的 `downloadCsv`），加载中或加载失败时禁用。它与项目行菜单里的“导出项目”是两个能力 |

**日期范围。** 指标和趋势共用同一个滚动窗口：周、月、季、年分别是含今天在内的近 7、30、90、365 天（`utils.GetPeriodRange`）。趋势接口回传 `start_date` 和 `end_date`；图上不另写范围，x 轴标签本身就是日期（接口的 `MM-DD` / `YYYY-MM` 显示成“11月8日”“2026年1月”），导出的 CSV 里带日期范围一行。周和月按天分桶；季和年按自然月分桶，所以首尾两个月可能是不完整月，图上的首尾柱不能当成整月金额解读。周期名称用“近 7 天”这类滚动说法，不写“本月”“本季度”。日历的自然月不等同于分析的“近 30 天”。

**渲染。** 趋势与统计并行加载，用同一请求代次或取消过期请求。Chart.js 实例在数据更新时更新 series，卸载时 `destroy()`，主题切换更新颜色。Tooltip 展示实际日期、实际值和计划值。另给屏幕阅读器或键盘用户可读的数据摘要或表格，不能让图表仅靠颜色或 hover 传递信息。

### 6.5 系统设置

原型展示的是“外观设置”标签，不代表默认页被改为外观，也不代表移除其他设置。保留 `/settings?tab=appearance` 深链及默认 `profile` 行为。访问未知或无权标签时回到可访问标签，不仅是在 UI 隐藏菜单。

**布局。** 页头“系统设置 / 管理账户和界面偏好”，其下一条横向的文字标签（ODS `Tabs` 的 `underline` 变体：一条细线，选中项底部 3px 下划条）。九个标签都在这一条上，顺序是个人信息、安全设置、外观设置、通知设置、数据同步、用户管理、字典管理（后两个仅管理员）、开发设置、关于；放不下时标签条自己横向滚动，被遮住的一侧渐隐，选中项自动滚进可视范围。内容区不套卡片，也不重复标签名：选中的标签就是标题。设置项是行式布局，左边标题和一句说明，右边控件，行间细线。表单、关于和同步配置都取外观页左列的宽度（约 64%），切标签时内容右边界不动。五个管理面板（用户、字典、数据同步、通知、令牌）顶部是一行工具条：左边行内统计，右边搜索和主操作。

| 项 | 默认／落地 |
|---|---|
| 界面主题 | 浅色／深色／跟随系统。复用现有 theme store 和 `auto` 存储值，不覆盖已有选择 |
| 江南动态场景 | 新增，默认开启。关闭时只显示静帧，不启动场景渲染循环 |
| 减少动态效果 | 新增，应用内默认关闭；系统 `prefers-reduced-motion` 开启时仍生效。两者任一为真就使用静帧，并减少 UI 过渡 |
| 液态玻璃效果 | 新增，默认开启。不支持滤镜或关闭后回落到实色材质，Dock 结构不改变 |
| 预览 | 外观页右列，静帧 `scene.webp` 的裁切（桥和柳），高度跟随左侧四行，夜雨主题下盖同一层 `--ods-color-scene-veil`。不实例化第二个 WebGL 上下文 |
| 持久化 | 三个新偏好由 `stores/appearance.ts`（Zustand）写入 `localStorage` 的 `zhusuan.appearance.v1`，坏值回落到默认。现有 `theme` 键和 `stores/theme.ts` 继续保留 |

开关即改即存，状态可读，文字说明在屏幕阅读器下与控件关联（`aria-labelledby` / `aria-describedby`）。个人信息与安全表单仍使用显式保存和现有验证。账户退出在个人信息标签底部的一行（当前账户 + “退出登录”）；组件展厅 `/design-system` 的入口在开发设置的工具条里。

### 6.6 登录

**布局。** 全屏一张清晰的江南静帧，不挂 Dock，不跑场景动画。右侧一张磨砂卡片（ODS `CloudPanel`），四角是海棠角，边缘 2px 近白的亮边，没有投影。卡片宽 `clamp(27rem, 38vw, 33rem)`，垂直居中，右边距约窗口宽度的 3.8%。静帧的裁切是 `background-size: max(120%, calc(100vh * 1.4055)) auto; background-position: 56% 40%`，让桥和人物落在左半边空处。06、07 两张原型画的是另一幅画，比例和饱和度都和首页那张不同；实现用的是首页的静帧，只对齐了人物和桥拱的位置。

**内容。** 楷体标题“欢迎回来”，标题下一道向右变细变淡的杏色笔触，一句说明“登录后继续查看项目与收款进度”。两个输入框没有外部标签，文字在框内，左侧图标（人、锁），密码框右侧是显示/隐藏。其下一行左右各一个复选框，再下是整行的主按钮“登录”。卡片右上角一枝梅，底边一带远山，都是从原型里抠出来的带透明通道的图，在内容下面，被卡片轮廓裁切。

**与原型有意的差别。**

| 原型里有 | 实现 | 原因 |
|---|---|---|
| `进入演示` 按钮 | 不做 | 前后端都没有演示模式 |
| `忘记密码` 链接 | 不做 | 没有自助重置，只有管理员能在用户管理里重置 |
| `安全连接已启用` 页脚 | 不做 | 应用并没有计算或保证这件事 |
| 一个 `记住我` | 保留“记住用户名”“记住密码”两个 | 记住密码会把密码写进系统凭据存储，是单独的一次同意；合并后，只勾了记住用户名的老用户会在下次登录时被悄悄存下密码 |
| 框内文字 `账号` | `用户名 / 邮箱 / 手机号` | 后端三种都收，写出来才知道 |
| 中青实心、白字的主按钮 | ODS 主按钮（浅青底墨绿字） | 4.1 明确不用深色实心按钮；白字在该底色上对比度只有 3.2–4.4:1 |
| 无 | 保留错误提示、“登录中...”“读取登录信息...”等状态 | 原型只画了空闲态 |

原型没有的主题切换按钮、Logo 和“Orange”字标一并去掉；主题在登录后的外观设置里改，登录页跟随已保存的主题，夜雨主题用 `--ods-color-scene-veil` 压暗同一张图。登录页有窗口拖动区（和应用壳同一个 `app-titlebar-drag-region`）。

### 6.7 页面未找到

任何未匹配的地址（`*`，挂在根路由下、`ProtectedRoute` 和 `AppLayout` 之外）显示这一页。壳与登录页相同，卡片内容居中：大号斜体衬线“404”（`--ods-font-family-numeral`，`--ods-gradient-text` 渐变），数字前两位下面一道笔触，楷体标题“页面走丢了”，两行说明，主按钮“返回首页”（去 `/dashboard`，未登录会被带到登录页），次按钮“返回上一页”，底部一行雨云图标 + “雨雾未散，路径可重寻”。“返回上一页”只在应用内确实有上一页时出现（直接打开一个错误地址时没有地方可回）。

## 7. 江南动效实现

### 7.1 渲染分层与资产清单

**WebGL2 负责水面倒影、薄雾和柳枝形变；Canvas 2D 负责细雨、雨滴落水和可选的微弱涟漪。** Dock、金额、人物交互外的业务控件保持 DOM。使用 React 组件包一层原生 WebGL2，不引入 Three.js。只有出现复杂场景管理需求时再评估依赖。

**首期资产现状。** 手头只有 1487 × 1058 的合成原型图，没有分层母版。首期从原型图修掉窗口按钮、摘要和 Dock 得到无 UI 静帧，放大到 2× 作为唯一场景贴图，再用程序生成的水域遮罩和柳枝权重图驱动着色器。水面、柳枝在同一张贴图上做位移，人物和桥体不在任何遮罩内所以保持静止。下表是拿到分层母版后的目标清单，首期实际交付见表后说明。

| 建议文件／资产 | 内容与规格 | 可独立验收 |
|---|---|---|
| `scene-fallback.webp` | 工作台完整静帧，无 Logo、无假窗口按钮、无 Dock 和图表 | 无 WebGL 和离线仍可用 |
| `scene-business.webp` | 同色同构图无人物静帧，也可用于设置预览的缩略版 | 所有业务页共用，不播放动效 |
| `sky-village.webp` | 天空、远山、白墙黛瓦、植被和岸线的静态底板；雨丝不烘进动态底板 | 可独立用于水面反射贴图 |
| `bridge.webp` + `bridge-near-rail.webp` | 石桥底层与近侧石栏遮罩，保留正确透明边缘 | 人物能位于桥面且被前栏遮住 |
| `child-hanfu.webp` | 透明分层角色，含站姿、微笑、发髻；首期可全程静态 | 不出现重复人物或裁切脸部 |
| `willow.webp` + 锚点／权重 | 柳树主枝、3–6 组垂枝，根部权重为 0、末端逐渐增大 | 根部不漂，叶端自然错相 |
| `water-mask.webp` | 水面区域灰度遮罩，桥洞水面与岸线对齐 | 水波不穿越石栏、人物或陆地 |
| 低分辨率噪声／可选水面底板 | 薄雾和水纹采样，无高对比重复花纹 | 单独禁用也不产生空黑画面 |

首期实际交付在 `frontend/src/assets/jiangnan/`：`scene.webp`（无 UI 静帧，含人物）、`scene-business.webp`（缩小并预模糊的业务页背景，避免运行时全屏 blur）、`scene-masks.webp`（R 通道水域、G 通道柳枝权重）。生成脚本在 `frontend/scripts/build-jiangnan-scene.py`，输入是 `docs/prototypes/01-workbench.png`。

原型 PNG 不得连同内嵌 Dock、数据面板及三色窗口控件整张当作运行时背景。拿到母版后应另做分层资产。建议场景母版 2560 × 1824 左右，渲染版可备 1920 和 1280 宽两档，透明层支持正确 alpha。各层共享归一化坐标与同一裁切变换。绘制顺序可设为远景 → 桥体与岸线 → 角色 → 近侧石栏 → 水面（严格按水域遮罩合成）→ 薄雾／柳枝 → Canvas 2D 降雨 → DOM。水面贴图采样只用场景层，不纳入 Dock、文字或透明工作面板。

### 7.2 动效参数起点

| 对象 | 建议初值 | 禁止出现 |
|---|---|---|
| 远雾 | 18–35s 的极慢漂移，透明度低，变化连续 | 整屏呼吸曝光、硬边云条 |
| 水面倒影 | 根据水面深度增加位移，屏幕约 0.6–2.4px；渐隐扰动从水线向下增强 | 水线错位、桥体本身抖动、整块纹理横移 |
| 柳枝 | 每组 3.5–8s 错相，枝端位移约 4–14px，近树干几乎静止 | 整棵树刚体摇摆、同步钟摆、抖动 |
| 雨丝 | 参考窗口 70–120 条轻量粒子，斜角约 8–14°，小雨而非暴雨 | 高对比密集雨墙、跨 Dock 叠画 |
| 水波圈 | 3–8 个同时可见，0.8–1.8s 生命周期，扁椭圆并按景深缩放 | 水面外生成、等距整齐同步扩散 |
| 女童 | 首期静态。可选衣袖或系带极轻摆动，脸和站位固定 | 大幅眨眼循环、跳动、变形或吸走注意力 |

参数是起点，需在 1280 × 800 和 1440 × 1024 看至少 30 秒。视觉优先级始终是桥和人物位置正确，其次是运动自然。

### 7.3 生命周期、降级和性能

```text
加载静帧 → 判断工作台、可见、用户偏好与系统动效设置
  ├─ 不满足 → 静帧，无 RAF
  ├─ 满足且 WebGL2 初始化成功 → WebGL2 + Canvas 2D
  ├─ WebGL2 不可用或编译失败 → 静帧 + 轻量 Canvas 2D（可用时）
  └─ 2D 也失败 / 主动关闭 / 减少动态 → 静帧，业务照常
```

- 静帧先出现。高清资产与着色器稍后加载，首帧画出后再显出动效层。首次可用 Dock 和数据不等待 GPU 初始化。Canvas 栈设置 `pointer-events: none`、`aria-hidden="true"`。
- 用一套帧时钟协调两层。把帧间隔限制在合理范围，如 50ms，回到前台重置时间基准，避免雨粒子跳跃。适配 `ResizeObserver`，只在 CSS 尺寸、DPR 或质量档变更时重建绘制缓冲，禁止每帧 resize。
- 默认 WebGL DPR 上限 1.5，Canvas 2D 上限 1.5，低档 1.0 或降低内部渲染比例。主绘制面像素可先限在约 240 万。避免逐帧新建粒子、重复上传静态纹理、读回 GPU 或遍历 DOM。
- 目标：常规档尽可能接近 60fps，低档 30fps 仍流畅。建议连续采样后再降档，例如 2 秒持续超过约 22ms/帧就先降 DPR 与雨粒子；持续低于约 30fps 可回到简化或静态模式。避免阈值附近反复切换。
- 离开工作台、窗口不可见或最小化时停止 RAF。使用 `visibilitychange`，并在目标 Wails 版本验证窗口事件能否补足最小化场景。业务页停留时不保留一个无声运行的场景。工作台卸载时取消 RAF、解绑监听、断开观察器并释放纹理、程序、缓冲和画布引用。
- 捕捉 `webglcontextlost`，切回静帧；若允许恢复则在事件中 `preventDefault()`，`webglcontextrestored` 后重建 GPU 资源并按路由和设置决定是否恢复。Canvas 2D 与 WebGL2 使用两个独立 canvas。同一个 canvas 不能把 2D 当已创建 WebGL2 上下文的随时替代。
- 使用本地素材和本地字体，支持离线。首屏静帧建议压至约 0.5–0.9MB，按需加载动态资源，不用长视频替代整个场景。记录所测系统、客户端、分辨率、DPR、设备和动态档位，不把“开发浏览器正常”当作三端通过。

| `useAppearanceStore` | 主题 store 派生值、场景和玻璃开关 | 版本化读写、与系统动效合并、暴露实际渲染偏好 |
