# 合同回款与实际收款

实施依据：2026-11-22 用户确认，日常流程是收到一笔钱就录入一笔，不维护收款计划；随后明确合同统计随周期切换，合同按签约日期归属。

## 产品规则

项目合同金额定义应收总额，实际收款记录定义已经收到的金额。项目履约状态与收款状态独立，进行中、已完成或归档不会改变合同余额的计算。

数据分析分为两个区域：

- **本期收款**：所选自然周期内的实际到账金额、笔数和趋势。
- **合同回款**：所选周期签约的合同总额，以及这批合同截至现在的合同已收、合同未收和收款率。

工作台只显示“合同已收”和“合同未收”，去掉底部现金行。点击原饼图循环全部、本年签约、本月签约，两个金额和饼图同步切换。当前与下一范围由原按钮的 tooltip 和无障碍名称说明，不额外添加说明行。日历以实际到账日期呈现已确认收款。

## 金额定义

先按签约日期选出合同集合 S；“全部”包含所有合同。对集合内每个项目，设合同金额为 C，截至现在的全部已确认收款合计为 R（包括跨期到账）：

| 指标 | 计算 |
| --- | --- |
| 合同总额 | 对 S 汇总 ΣC |
| 该批合同实际累计到账（API received_total） | 对 S 汇总 ΣR，包含超收及实际日期缺失的历史已确认收款 |
| 合同已收（页面与环图） | 对 S 汇总 Σmin(max(R, 0), C) |
| 合同未收 | 对 S 汇总 Σmax(C − R, 0) |
| 超收金额 | 对 S 汇总 Σmax(R − C, 0) |
| 合同收款率 | 合同已收 ÷ 合同总额；无合同金额时显示空值 |
| 本期收款 | 所有所属合同中，状态为已确认、实际到账日期位于所选范围内的金额之和 |
| 本期收款笔数 | 同一实际到账日期范围内的已确认记录数，不受签约批次筛选影响 |

未收余额逐个项目计算。某项目超收不得抵消另一个项目的未收款。未收余额本身不代表逾期；没有付款期限时不展示逾期比例或到账偏差。

例如去年签约的合同在本月到账：它进入本月实际收款与趋势，但不进入本月签约合同的已收、未收。反过来，本月签约合同在下月到账后，这笔钱会更新本月签约批次的当前余额；历史周期展示当前余额，属于该批合同的回款情况，不是期末历史快照。

## 时间范围

本周为周一到周日，本月、本季、本年使用自然日历。自选年或月沿用明确的自然范围。结束日期包含整天，查询使用开始日到结束日次日的左闭右开区间。

合同归属使用 `projects.contract_date`，不以项目开始日期或创建时间代替。缺少签约日期的历史合同只进入“全部”，不虚构年月。合同的已收与未收计算包含该批合同截至现在的已确认收款，不再对这些收款按实际到账日期二次筛选。

全部现金范围包含所有已确认收款；没有实际日期的历史记录仍计入累计现金金额和笔数，但不虚构日期加入某月的趋势。累计趋势只画有实际日期的记录，按月汇总。

## 录入和历史兼容

- 新项目可以不录收款。收到钱后，再添加一笔或多笔收款记录，不受一次性或分期付款模式限制。
- 新记录默认为已确认收款，实际到账日期默认今天，可修改；金额和实际日期必填，款项分类选填。
- 已有款项的 ID、金额、状态、备注和实际到账日期保留。实际日期省略的更新不得覆盖原非空日期。
- 历史待收或逾期记录不会自动变成已收；只有用户明确登记到账才进入实际收款。
- 只编辑项目资料时，未修改的已有款项不重新写入，也不强制补齐历史缺失日期。
- 保存记录的成功确认状态与签名保留，部分失败后只重试未完成操作。
- 详情、编辑与项目导出按实际到账日期从早到晚，同日按记录 ID 排序；保存响应补齐 ID 后再次排序，避免部分成功时编号错位。最近收款独立显示最新一笔。
- 旧计划日期字段与旧统计接口保留兼容，不删除历史数据或自动生成历史计划。

## 接口

`GET /api/v1/dashboard/receipt-overview` 返回两套独立金额：五个合同字段按所选签约周期统计该批合同截至现在的余额，两个期间现金字段按实际到账日统计所有所属合同。

`contract_total`、`received_total`、`contract_received`、`outstanding_total`、`overpaid_total`、`period_received`、`period_count`、`start_date`、`end_date`。

新增 `GET /api/v1/dashboard/receipt-trend`，返回实际收款趋势，使用既有 labels/actual_values 结构；计划曲线不用于新页面。

款项写入支持 `actual_date`；`plan_date` 和 `stage` 可省略。新客户端提供实际到账日期与已确认状态；旧计划日期请求继续兼容。日期请求统一为 `YYYY-MM-DD`，不通过 UTC 转换改变源日历日期。

款项日期列表使用 `date_field=actual` 时，只查询已确认且实际日期在范围内的记录。旧列表默认仍按原计划日期契约。

## 验收重点

- 无收款计划但存在合同余额时，能正确显示未收余额。
- 周期切换同步改变签约合同总额、合同已收、合同未收和饼图；现金金额、笔数与趋势独立按实际到账日切换。
- 所选期内没有签约合同但有前期合同到账时，合同字段为零，现金金额、笔数和趋势仍正确显示。
- 跨用户隔离、超收隔离、跨期到账、缺失历史日期、自然周期边界均有回归。
- 项目无收款创建、逐笔到账、多笔编辑、部分失败重试及历史未确认记录保护均可运行。
- 汇总使用数据库聚合，不逐项目加载或发起 N+1 查询；沿用现有索引与事务顺序。
- 以独立数据库验证页面与 API，不修改真实账本或已安装应用；发布由后续用户指令决定。

初次固定全量口径的验收留存于 [receipt-accounting-verification.json](receipt-accounting-verification.json)；该口径已由上述新要求替代。最新签约周期验收见 [contract-scope-verification.json](contract-scope-verification.json)。
